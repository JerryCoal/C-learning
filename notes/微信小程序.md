# 微信小程序设计
## 页面跳转代码详解
### 1. 全局页面配置 - app.json
    json
    应用
    "pages": [
    "pages/login/login",      // 第一行 = 启动页
    "pages/index/index",      // 主页
    "pages/logs/logs"         // 日志页
    ]
    作用：

    定义小程序的所有页面
    第一行 pages/login/login 是启动页，小程序启动时自动打开
    确保其他页面可以通过路径访问
### 2. 登录页跳转主页 - login.ts
    代码位置：第 42-44 行

    typescript
    应用
    wx.redirectTo({
    url: '/pages/index/index'
    })
    解析：

    wx.redirectTo() - 微信小程序跳转 API
    url: '/pages/index/index' - 目标页面路径
    效果：关闭当前登录页，打开主页，用户无法返回到登录页
    完整流程：

    用户输入用户名密码（第 22-27 行）
    验证通过后保存登录状态（第 32-33 行）
    显示登录成功提示（第 35-38 行）
    延迟 1.5 秒后跳转到主页（第 41-45 行）
### 3. 主页检查登录状态跳转 - index.ts
代码位置：第 19-21 行

typescript
    应用
    wx.redirectTo({
    url: '/pages/login/login'
    })
    解析：

    在页面加载时自动检查登录状态
    如果未登录，强制跳转到登录页
    使用 wx.redirectTo() 防止用户返回到需要登录的页面
    完整流程：

    页面加载时触发 attached() 生命周期（第 8-11 行）
    调用 checkLoginStatus() 方法（第 14-33 行）
    检查本地存储的登录状态（第 16 行）
    未登录时跳转到登录页（第 19-21 行）
### 4. 退出登录跳转 - index.ts
    代码位置：第 52-54 行

    typescript
    应用
    wx.redirectTo({
    url: '/pages/login/login'
    })
    解析：

    用户确认退出后清除登录状态（第 42-43 行）
    跳转回登录页重新登录
    确保用户必须重新登录才能访问主页
    完整流程：

    点击退出按钮触发 handleLogout()（第 34 行）
    显示确认对话框（第 35-39 行）
    用户确认后清除登录状态（第 42-43 行）
    延迟跳转到登录页（第 51-55 行）
    关键跳转 API 对比
    wx.redirectTo() - 替换跳转
    typescript
    应用
    wx.redirectTo({
    url: '/pages/target/target'
    })
    特点：关闭当前页，打开目标页
    适用场景：登录后、退出登录等无需返回的场景
    wx.navigateTo() - 保留跳转
    typescript
    应用
    wx.navigateTo({
    url: '/pages/target/target'
    })
    特点：保留当前页，打开目标页，可以返回
    适用场景：正常的页面导航
    wx.switchTab() - 切换 Tab
    typescript
    应用
    wx.switchTab({
    url: '/pages/index/index'
    })
    特点：跳转到 Tab 页面
    适用场景：底部导航栏切换
### 总结
    在你的小程序中，页面跳转主要通过以下方式实现：

    配置文件：app.json 定义页面结构和启动页
    登录跳转：wx.redirectTo() 从登录页到主页
    权限控制：主页自动检查登录状态，未登录则跳转
    退出跳转：清除登录状态后返回登录页
    所有跳转都使用 wx.redirectTo() 确保页面流转的单向性和安全性。
